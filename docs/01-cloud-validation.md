Текущая конфигурация bootstrap содержит четыре ресурса: один сервисный аккаунт, назначение роли для сети, бакет и назначение роли для S3. При создании с нуля ожидаемый план — `4 to add, 0 to change, 0 to destroy`.

По решению владельца инфраструктура и S3 backend используют один аккаунт. Лишний отдельный аккаунт backend удалён через Terraform после переноса прав. Существующий `service-acc` этой конфигурацией не изменялся.

После объединения повторный `terraform plan -detailed-exitcode` завершился с кодом 0 и результатом `No changes`. Оба выхода, `terraform_service_account_id` и `state_service_account_id`, указывают на `ajeaaeokme5na3bguqmu`.

State bootstrap находится в `infrastructure/bootstrap/terraform.tfstate` и исключён из Git. Файлы локального профиля CLI и планы находятся в `.tools/`, также исключённой из Git.

## Сеть и удалённое состояние

Владелец самостоятельно создал авторизованный JSON-ключ и статический S3-ключ. По метаданным проверено, что оба принадлежат аккаунту `ajeaaeokme5na3bguqmu`. Значения секретов не выводились в чат и не включены в отчёт.

Основная конфигурация применялась с JSON-ключом сервисного аккаунта, без IAM-токена личной учётной записи. Для backend использован статический ключ того же аккаунта.

| `diplom-network` | `enppkt7gcb9ffjrinh9t` | VPC |
| `diplom-ru-central1-a` | `e9b6kk2vq6spoog2mspt` | `ru-central1-a` / `10.10.0.0/24` |
| `diplom-ru-central1-b` | `e2l93u7ertnbbnunf0lf` | `ru-central1-b` / `10.20.0.0/24` |
| `diplom-ru-central1-d` | `fl8takd3k5uf2bctlnv8` | `ru-central1-d` / `10.30.0.0/24` |

State основной конфигурации хранится в `s3://diploma-tfstate-bbe2400261af/diploma/infrastructure.tfstate`. S3 backend и `use_lockfile = true` проверены; состояние прочитано обратно через `terraform state pull`.

Проверка повторяемости:

1. Первоначальное создание: `4 added, 0 changed, 0 destroyed`.
2. План после создания: `No changes`, код завершения 0.
3. Проверенный `plan -destroy` применён: `0 added, 0 changed, 4 destroyed`.
4. Та же конфигурация применена повторно: `4 added, 0 changed, 0 destroyed`.
5. Последующий план: `No changes`, код завершения 0.
6. Проверены четыре ресурса в удалённом состоянии, сохранение lineage и увеличение serial. Повторное создание не потребовало изменения ключей или ручного создания ресурсов в консоли.

По просьбе владельца аккаунт, сеть, подсети и метки проекта переименованы с `diploma` на `diplom`. Переименование выполнено на месте, без смены ID аккаунта и сетевых ресурсов. Имя бакета и путь состояния оставлены прежними по отдельному указанию владельца.

После переименования оба модуля проверены повторно: `No changes`. В S3 подтверждены четыре сетевых ресурса с именами `diplom-*`, прежний ID сети и сохранённый lineage. Serial состояния увеличился с 1 до 4 за цикл проверки и переименование.
