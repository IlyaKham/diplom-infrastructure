# Квоты для второго этапа

Проверка выполнена через Cloud Quota Manager 17 ноября 2026 года для облака `b1g796p3nqrgb3h49s2f`, до создания платного мастера и рабочих ВМ.

Требуется региональный Managed Kubernetes и три рабочих узла: по одному в зонах `ru-central1-a`, `ru-central1-d`, `ru-central1-e`. Каждый узел: 2 vCPU, 4 ГиБ RAM, прерываемый, диск 64 ГиБ. В a/d используется HDD, в e — SSD.

## Итоговая конфигурация квот Compute Cloud

| Квота | Лимит после запроса | Необходимо минимум |
| --- | --- | --- |
| Объём HDD, `ru-central1-a` | 64 ГиБ, одобрено | 64 ГиБ |
| Объём HDD, `ru-central1-d` | 64 ГиБ, одобрено | 64 ГиБ |
| Объём SSD, `ru-central1-e` | 64 ГиБ, одобрено | 64 ГиБ |
| vCPU, в каждой из a/d/e | 2 | 2 |
| RAM, в каждой из a/d/e | 16 ГиБ | 4 ГиБ |

Другие необходимые ресурсы проверены: квоты количества ВМ, групп ВМ, дисков, Kubernetes и публичных IP имеют запас. Квота сетей занята двумя существующими сетями, но новый кластер использует сеть диплома и дополнительной VPC не требует.

Идентификаторы квот для запроса:

| ID | Требуемое значение в API |
| --- | --- |
| `compute.hddDisks.size.ru-central1-a` | `68719476736` байт |
| `compute.hddDisks.size.ru-central1-d` | `68719476736` байт |
| `compute.ssdDisks.size.ru-central1-e` | `68719476736` байт |

## Результаты запросов

1. `atd6mrjaagd352g1bre8`: HDD в a/d одобрен до 64 ГиБ; HDD, CPU и RAM в b отклонены с предложением использовать a/d.
2. `atd52srqqduh3s05ljd4`: HDD в e отклонён, лимит остался 20 ГиБ.
3. `atdhuiqskdn2g9t1cal3`: SSD в e одобрен до 64 ГиБ. Это позволило сохранить три зоны и требования Managed Kubernetes.

Итог: размещение a/d/e с HDD/HDD/SSD. Типы дисков зафиксированы в `worker_disk_types`. Кластер не запускался до получения необходимых квот, чтобы не оплачивать мастер без возможности создать все рабочие узлы.

## Как подать запрос самостоятельно

Для воспроизведения в другом облаке открой консоль Yandex Cloud → **Квоты** → **Compute Cloud**, проверь зональные лимиты CPU, RAM и нужного типа диска. При необходимости запроси значения из таблицы. Наличие подсети в зоне само по себе не подтверждает возможность выделить там рабочую ВМ.

Перед созданием кластера квоты нужно проверить повторно. Одного успешного Terraform plan недостаточно для проверки квот Compute Cloud: ограничения рабочего узла проверяются при выделении его ВМ и диска.

Источники: [недостаточная квота при создании узлов Kubernetes](https://yandex.cloud/ru/docs/troubleshooting/compute/known-issues/the-limit-on-maximum-number-of-cores-has-exceeded), [управление квотами](https://yandex.cloud/ru/docs/quota-manager/operations/list-quotas), [минимальный диск группы узлов](https://github.com/yandex-cloud/terraform-provider-yandex/blob/v0.248.0/docs/resources/kubernetes_node_group.md).
